# Shard Rescue｜雙重校驗檔案還原工具

錄音歸檔後，一整個儲存卷離線，其他兩個卷各有一處損壞。只要每一條帶仍有四片可用，Shard Rescue 就能讀取剩下的分片，重建錄音，並在交付前核對原始檔的 SHA-256。

## 重現錄音還原

使用 Python 3.12 與標準函式庫，在專案根目錄執行。

```sh
python demo.py
python -m unittest -v
```

示範產生一秒鐘的單聲道 WAV，共 48,000 個取樣幀、96,044 位元組。封存後將其中一卷移出，截短第一條帶的一片資料，並翻轉第二條帶校驗片的一個位元。兩條帶各有兩片無法使用。還原後逐位元組與原始錄音比對，再以 WAV 讀取器核對幀數。所有故障注入都在暫存目錄執行。[可執行示範](demo.py)

| 條帶 | 失去的分片 | 讀回方式 |
| --- | --- | --- |
| 0 | D1 整卷離線、D3 檔案截短 | 用 P、Q 聯立求回 D1 與 D3 |
| 1 | D1 整卷離線、Q 有一個位元翻轉 | 用 P 和其餘三片資料求回 D1 |

示範也會重建整個 D1 替換卷，將兩片共 32,768 位元組逐片與移出的原卷比對。接回 D1 後再次巡檢，每條帶的失效分片從兩片降為一片，可以再承受一片故障。

## 巡檢與換卷

```sh
python shard_rescue.py scrub recording-archive
python shard_rescue.py rebuild-volume recording-archive d1 replacement-d1
```

`scrub` 以唯讀方式逐片核對可信清單，列出異常條帶、分片名稱，以及遺失、長度異常、雜湊不符或讀取失敗的原因。退出碼 0 表示全部分片通過，2 表示受損且各條帶仍可還原，3 表示至少一條帶超過修復能力，1 表示指令執行失敗。

`rebuild-volume` 在封存目錄外建立全新的替換卷，接受任一資料卷或校驗卷。目標卷中通過驗證的分片可以直接複製，遺失或損壞的分片則從其餘卷重建並核對 SHA-256。請在卷內容穩定時操作，命令成功退出後才將替換卷接回對應位置，再跑一次 `scrub`。遇到不可重建的條帶會清除本次輸出。系統斷電可能留下部分寫入的目錄，重新執行時請指定另一個新目錄。

測試涵蓋全部 30 種「替換卷 × 第二個失效卷」組合，並與故障注入前的分片逐位元組比對。[換卷測試](test_rescue.py)

## 封存自己的檔案

```sh
python shard_rescue.py pack recording.wav recording-archive
python shard_rescue.py restore recording-archive recovered.wav
```

`pack` 需要新的目錄名稱，在六個子目錄分別存放 D0 到 D3、P 和 Q，最後發布 `manifest.json`。單片固定為 16 KiB，每條帶容納 64 KiB 原始內容，末尾補零。可將六個子目錄分放在不同媒體，另存可信的清單副本，讀回時依原目錄結構放置現存分片。把六個子目錄放在同一顆硬碟只適合示範局部分片損壞。

`restore` 以清單中的長度與雜湊辨識缺失、截短或內容損壞的分片。它逐條帶讀取資料，記憶體另需容納分片清單。若任一條帶有三片失效，指令會回報該條帶的位置與失效數量。還原過程寫入輸出目錄中的暫存檔，通過整檔 SHA-256 核對後才替換指定輸出。使用者需保留可信清單，才能核對還原資料。

## 兩片資料同時遺失時如何求回

P 是四片資料逐位元組的 XOR。Q 先在 GF(256) 中分別乘上 1、2、4、8，再做 XOR，約化多項式為 0x11D。扣除仍可讀的資料後，P 與 Q 各留下一條方程式。兩個遺失位置有不同的係數，因此可求得兩個未知位元組。六片中任選四片即可還原該條帶的原始資料。[實作](shard_rescue.py) · [P、Q 校驗的數學推導](https://www.kernel.org/pub/linux/kernel/people/hpa/raid6.pdf)

測試走訪六種單片遺失與全部十五種雙片遺失組合，逐位元組比對原始資料。另有手算校驗向量、空檔與邊界長度、失敗保留既有輸出，以及兩條帶錄音修復。Windows 與 Linux CI 均執行命令列測試與示範。[測試原始碼](test_rescue.py) · [CI 流程](.github/workflows/ci.yml)
